# Student Performance Prediction Using Machine Learning

StudyWise is a local Flask web application and end-to-end ML mini-project. It accepts a small set of learning-habit inputs and returns an estimated examination score, a category and study suggestions. The project is designed to make the workflow understandable to a BTech student.

> **Data notice:** `dataset/student_performance.csv` is generated by `train_model.py` using a documented illustrative formula plus random variation. It contains synthetic records, not real student data. Metrics describe only a held-out part of this synthetic dataset. Predictions are educational estimates, not guaranteed examination results or a basis for academic decisions.

## Abstract

This project demonstrates a regression workflow that turns student study indicators into an estimated score from 0 to 100. It creates and inspects a synthetic dataset, cleans it, preprocesses numeric and categorical features with a scikit-learn pipeline, compares Linear Regression, Decision Tree and Random Forest regressors, and saves the best model. Flask serves the pipeline through a responsive web interface and JSON API.

## Problem statement

Students learning ML need a complete example connecting data preparation, evaluation, model persistence, backend inference and a usable interface. The project illustrates that flow with learning-related factors while avoiding any claim that generated data reflects actual students.

## Objectives

- Demonstrate data loading, preview, missing-value inspection, duplicate removal and cleaning.
- Explore the generated features and visualize distributions and correlations.
- Compare three regression algorithms using one reproducible train/test split.
- Avoid preprocessing leakage by fitting imputers, scaling and categorical encoding only on training data inside the model pipeline.
- Serve validated predictions and suggestions through Flask.
- Report MAE, MSE, RMSE and R² using regression terminology.

## Existing and proposed systems

**Existing learning approach:** A beginner may see separate snippets for training, evaluation and a web form, with little explanation of how they connect. A real-world deployment would also require representative, consented data and careful validation.

**Proposed demo:** One reproducible script creates the explicitly synthetic data, cleans and explores it, trains comparable pipelines, selects the model with lowest test RMSE, and writes model and metric artifacts. A Flask app loads that saved pipeline and presents estimates with clear limitations.

## Technologies

Python, Pandas, NumPy, Matplotlib, Seaborn, scikit-learn, Joblib, Flask, HTML, CSS and JavaScript.

## Dataset

The training script generates 1,200 rows with these predictors: daily study hours, attendance percentage, previous score, assignment completion percentage, sleep hours, internet access and extracurricular participation. The target is `exam_score`, bounded to 0–100. A seeded random generator makes the synthetic dataset reproducible. Its target is an illustrative formula with noise; this is not a source of real academic evidence.

Training prints the first five records, missing counts, and cleaned row count. The generated CSV is saved to `dataset/student_performance.csv`. `models/model_info.json` contains the preview, cleaning summary, split seed, model metrics and selection. No intended missing values exist in generated records, but the training workflow checks missingness and the preprocessing pipeline includes imputers.

## Machine learning algorithms

- **Linear Regression:** baseline linear model.
- **Decision Tree Regressor:** learns piecewise rules; depth and leaf size are constrained to reduce overfitting.
- **Random Forest Regressor:** averages many randomized trees.

All candidates use the same 80/20 split (`random_state=42`). Selection is based on lowest test RMSE. MAE and RMSE are score-point errors; MSE is squared score-point error; R² summarizes variance explained relative to a constant baseline and can be negative.

## Architecture

```text
train_model.py
  ├─ generate synthetic CSV → inspect / clean / EDA
  ├─ train/test split → preprocessing + regressor pipelines
  ├─ compare metrics → choose lowest-RMSE pipeline
  └─ save models/student_model.joblib + model_info.json + charts

Browser (HTML/CSS/JS) → Flask routes → saved sklearn pipeline
                         ├─ pages: /, /predict, /dashboard, /about

                         └─ GET /api/model-info (metrics / metadata)
```

## Installation and execution

From a terminal in the project folder:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python train_model.py
python app.py
```

Open <http://127.0.0.1:5000>. For macOS/Linux, activate with `source .venv/bin/activate`. Run `python train_model.py` again after changing the training data or pipeline. The dataset, fitted model, JSON metrics and charts are generated locally.

## GitHub Pages demo

The `docs/` folder is a static browser-only companion site. A GitHub Actions workflow deploys it to Pages on pushes to `main`; the workflow requests Pages enablement. Its predictor applies the selected Linear Regression model's learned coefficients in JavaScript. GitHub Pages cannot host the Flask server, so `/api/predict` and the Python backend are available only when running locally as described above. The static predictor is for demonstration and carries the same synthetic-data limitations.

Once the first Pages deployment finishes, the site is available at <https://revathikanchu931-png.github.io/student-performance-prediction/>.

## Routes

- `GET /` — home page
- `GET /predict` — prediction form
- `POST /api/predict` — JSON prediction request
- `GET /dashboard` — dataset and model dashboard
- `GET /about` — project overview
- `GET /api/model-info` — training metadata and metrics

Example API request:

```json
{
  "student_name": "Demo learner",
  "study_hours": 3.5,
  "attendance": 88,
  "previous_score": 72,
  "assignment_completion": 90,
  "sleep_hours": 7.5,
  "internet_access": "Yes",
  "extracurricular": "Yes"
}
```

The response includes `predicted_score`, `category`, `explanation` and `suggestions`. The score is clipped to 0–100. Categories: Excellent (85–100), Good (70–<85), Average (50–<70), Needs Improvement (<50).

## Results and evaluation

The training script computes MAE, MSE, RMSE and R² for each candidate on the held-out split and writes actual results to `models/model_info.json`. The dashboard reads those saved results and displays a model comparison chart, numeric feature-correlation heatmap and score distribution. The selected model is the measured lowest-RMSE candidate for that run; no accuracy percentage is claimed because this is a regression task. Regenerate artifacts with `python train_model.py` to reproduce them. Small floating-point differences can depend on library versions.

## Validation and testing

The API requires numeric inputs in these ranges: study and sleep hours 0–24; attendance, previous score and assignment completion 0–100. Internet and extracurricular values must be `Yes` or `No`. Invalid JSON and invalid fields receive HTTP 400 JSON errors. The frontend also uses browser form validation. The model clamps its estimate to the target range.

After training, a simple API smoke check can be made with PowerShell:

```powershell
$body = '{"student_name":"Demo learner","study_hours":3.5,"attendance":88,"previous_score":72,"assignment_completion":90,"sleep_hours":7.5,"internet_access":"Yes","extracurricular":"Yes"}'
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/api/predict -ContentType 'application/json' -Body $body
```

## Limitations

- Synthetic formula-driven records do not capture real learning, assessment or student diversity.
- Metrics on a random split of synthetic data do not establish real-world validity or fairness.
- The suggestion rules are simple heuristics, not personalized educational advice.
- This demo has no authentication, persistence of user inputs, model monitoring or deployment hardening.
- Inputs are not used to infer causal effects; associations in a generated dataset are not causal evidence.

## Simple presentation and viva explanation

**One-minute explanation:** “My project is a Flask web app that demonstrates a complete machine-learning regression workflow. A Python script generates clearly labeled synthetic student-study data, cleans and explores it, then compares Linear Regression, Decision Tree and Random Forest models using MAE, MSE, RMSE and R² on the same test split. Preprocessing and the selected model are saved together as a scikit-learn pipeline. The website sends validated form data to Flask, which returns a score estimate, category and simple study suggestions. Since the data is synthetic, the result is only for learning and is not a real exam prediction.”

**Viva questions and simple answers**

1. **Why is this regression?** The output is a numeric score; categories are derived afterward from that score.
2. **What is the target variable?** `exam_score`, the generated score between 0 and 100.
3. **Why use a train/test split?** To evaluate on records the model did not use for fitting.
4. **What is data leakage?** When information from test data influences training or preprocessing, making evaluation too optimistic. The pipeline fits transformations on training data only.
5. **Why encode categories?** Most estimators need numeric inputs, so Yes/No fields are one-hot encoded.
6. **What does MAE mean?** The average absolute difference between predicted and actual test scores, in score points.
7. **What does RMSE mean?** The square root of average squared error; it is in score points and penalizes larger errors more.
8. **What is R²?** A comparison of model error to predicting the test-set mean; it may be below zero.
9. **Why compare multiple models?** Different models capture different relationships; a shared split and metrics make comparison fairer.
10. **Why is the dataset synthetic?** It allows a self-contained demo without presenting private or fabricated records as real data.
11. **How is the best model chosen?** The pipeline with the lowest test RMSE is selected and saved with Joblib.
12. **What does Flask do?** It serves the pages, validates API data and calls the saved model.
13. **Are predictions guaranteed?** No. They are illustrative estimates based on synthetic training data.
14. **What would improve a real deployment?** Representative consented data, stronger external validation, privacy controls, fairness analysis and domain review.
